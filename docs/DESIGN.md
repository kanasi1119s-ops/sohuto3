# 設計メモ: オフライン見積・請求書メーカー

## 背景・ターゲットユーザー

個人事業主・小規模事業者向け。クラウド会計SaaSは月額課金＋データを外部に預ける前提のものが多く、
「取引先情報を外部サーバーに置きたくない」「月額課金ではなく買い切りがいい」というニーズに対して、
簡易な見積書・請求書作成に特化したローカル完結ツールを提供する。

## 配布形態の選定理由

| 検討した形態 | 却下/採用理由 |
|---|---|
| L1 静的SPA（採用） | サーバー運用コストゼロ、インストール不要でZIP配布や静的ホスティングだけで済む。会計データという性質上「外部送信ゼロ」を訴求しやすい |
| L2 デスクトップアプリ（Tauri） | MVPとしては過剰。ブラウザで完結できる機能範囲なので、まずはL1で検証し、ファイルシステム直接操作やオフライン専用インストーラが必要になった場合にL2へ移行する |
| C1 Web SaaS | 複数端末同期や決済が本質でない限りサーバー運用コスト・法務対応（個人情報の預かり）が増えるため見送り |

## データモデル

- `Client`: 顧客情報（名前・住所・メール）
- `InvoiceDoc`: 見積書/請求書。`kind` で区別、品目配列 `LineItem[]`、税率、日付
- `CompanySettings`: 自社情報（会社名・住所・デフォルト税率・振込先）
- `BackupPayload`: 上記3つをまとめた JSON バックアップ形式（`formatVersion` でスキーマ変更に備える）

すべて Dexie(IndexedDB) の3テーブルに対応。サーバー同期は行わない。

## 画面構成

1. **見積書・請求書タブ**: 一覧 → 新規作成/編集フォーム（品目行の追加・削除、税込合計のリアルタイム計算、PDF出力ボタン）
2. **顧客タブ**: 顧客の追加・一覧・削除
3. **設定タブ**: 自社情報・デフォルト税率

グローバル操作としてヘッダーに「バックアップ書き出し」「バックアップ読み込み」を配置。

## 計算ロジック

`src/lib/calc.ts` に集約。小数点誤差を避けるため、行金額・税額・合計はすべて円単位で四捨五入する
（`Math.round`）。消費税の端数処理は「税抜合計に対して税率を掛けて丸める」方式（インボイス制度上の
複数の端数処理方式のうち最も単純な「合計に対して一括計算」を採用。品目ごとの端数処理には対応していない
ことを既知の制約として明記）。

## PDF生成

`src/lib/pdf.ts` で jsPDF を直接使用し、固定レイアウトのテキスト描画で見積書/請求書を生成する。
日本語フォントは埋め込んでいないため、日本語文字列は正しく描画されない制約がある（README参照）。

## セキュリティ設計

- 外部通信は一切行わない（fetchやXHRの呼び出し箇所なし）。
- ユーザー入力はReactのデフォルトのエスケープに任せ、`dangerouslySetInnerHTML` は使用しない。
- バックアップのインポートはJSON.parseした内容を型ガード（`isBackupPayload`）でチェックしてから
  Dexieに書き込む。任意コード実行につながる `eval` 等は使用していない。
