# 公開手順 (人間向け) - Phase 7 DevOps

このソフトウェアは L1（ブラウザ完結SPA）です。以下はビルド成果物を実際に公開・配布する際の手順です。**AIはこの手順を実行しません**（本番反映は人間の承認事項）。

## 1. 静的ホスティングでの公開（例: GitHub Pages）

```bash
npm run build
# dist/ の内容を任意の静的ホスティングにアップロード
```

- GitHub Pages を使う場合: リポジトリの Settings > Pages で `dist/` を配信するワークフローを有効化してください（`.github/workflows/ci.yml` はテストのみでデプロイは行っていません。デプロイ用ワークフローの追加・有効化は人間が判断してください）。
- 独自ドメインを使う場合: ドメイン取得・DNS設定は必ず人間が行ってください（本指示書の大前提2番）。

## 2. ZIP配布（オフライン配布・買い切り販売向け）

```bash
npm run build
cd dist && zip -r ../kinko-vault-v0.1.0.zip . && cd ..
```

生成した `kinko-vault-v0.1.0.zip` を BOOTH / Gumroad 等で配布する場合、実際のアカウント接続・課金開始・商品ページ公開は必ず人間が行ってください。

## 3. GitHub Releases（下書きまで）

下書き (draft) Releaseの作成はAIでも可能ですが、実際の公開（Publish）は人間が行ってください。タグ付け例:

```bash
git tag v0.1.0
git push origin v0.1.0
# その後、ビルド成果物のZIPを添付した draft Release を作成
```

## 4. コード署名・ストア提出

本アプリはL1（ブラウザ完結）のため、コード署名証明書やOSストア提出は不要です。将来L2（デスクトップアプリ化、Tauri想定）に移行する場合は、配布形態の再評価（PdMフェーズへの差し戻し）が必要です。
