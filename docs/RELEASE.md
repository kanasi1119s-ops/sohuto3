# 公開手順書（人間向け）

このドキュメントに記載する操作は、いずれも本サイクルでは実行していません（運用指示書により、
公開・課金に関わる操作は必ず人間の承認・実行を経る必要があるため）。

## 前提

- `npm run build` で `dist/` に静的ファイル一式が生成される。CI（`.github/workflows/ci.yml`）は
  push/PRごとに型チェック・テスト・ビルドを実行し、`dist/` をアーティファクトとしてアップロード済み。
- 本アプリはサーバー不要（L1: 静的SPA）。以下いずれかの方法で配布できる。

## 方法A: ZIP配布（買い切り販売向け）

1. `npm run build` を実行し、生成された `dist/` フォルダの中身をZIPに圧縮する。
2. 販売プラットフォーム（BOOTH / Gumroad 等）の商品ページにZIPファイルをアップロードする
   （★アカウント接続・実際の課金設定は人間が行う）。
3. 購入者は展開したフォルダ内の `index.html` をブラウザで直接開くか、簡易ローカルサーバー
   （例: `npx serve .`）経由で利用する。

## 方法B: GitHub Pages での無料公開（無料配布・デモ用途向け）

1. リポジトリの Settings → Pages で GitHub Actions をソースに設定する（★人間が実施。この設定自体が
   リポジトリの一部を外部公開する操作にあたるため今回は行っていない）。
2. `.github/workflows/ci.yml` に加えて、Pages用のデプロイワークフローを追加する（次サイクルで用意可能）。

## draft Release について

運用指示書では「GitHub Releases の正式公開はNG、下書き(draft) Releaseの作成までは可」とされていますが、
本セッションで利用可能なGitHub操作ツールにはRelease作成用のツールが含まれていなかったため、
本サイクルではdraft Releaseの作成を行っていません。人間が `gh release create v0.1.0 dist.zip --draft`
のようなコマンドで作成することを想定しています。
