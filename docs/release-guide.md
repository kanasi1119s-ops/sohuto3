# 公開手順書（人間向け）

**注意: このプロジェクトのオーケストレーター（自動化フロー）は、以下の作業を一切自動実行しません。** ここに書かれた内容は「人間が実行するための手順書」であり、実際のストア公開・ドメイン設定・課金設定・入稿・発注などは必ず人間が判断し、人間の手で行ってください。

## 1. 事前チェックリスト
- [ ] `docs/rules.md` を読んで実際に人間同士（またはAI相手）で1〜2回プレイし、面白さ・バランスに納得できるか確認した
- [ ] `docs/legal-checklist.md` の★印（商標の正式調査、特商法表記）に対応した
- [ ] ゲームタイトル「ラインクラフト」で公開してよいか最終決定した（変更する場合は `index.html` の `<title>` と `package.json` の `name`、`docs/rules.md` 冒頭を合わせて更新）

## 2. ローカルでの起動確認
```bash
npm install
npm run dev      # http://localhost:5173 で起動確認
npm run test     # ユニットテスト
npm run build    # 本番ビルド（distフォルダが生成される）
npm run preview  # ビルド成果物をローカルで確認
npm run simulate # AIシミュレーションでバランスを再確認（任意）
```

## 3. GitHub Pages で公開する場合
1. リポジトリの Settings → Pages で、Source を「GitHub Actions」に設定する。
2. 以下のような追加ワークフロー（`.github/workflows/deploy.yml`）を人間が作成し、`npm run build` の成果物（`dist/`）を GitHub Pages にデプロイする（`actions/deploy-pages` 等を利用）。
   - このリポジトリには **ビルドを確認するCI（`.github/workflows/ci.yml`）のみ** を用意しており、実際のデプロイ用ワークフローは含めていない（=本番公開を自動実行しないため）。
3. デプロイ後、公開URLで実際に遊べることを人間が確認してから、SNS等で告知する。

## 4. itch.io で公開する場合（HTML5ゲームとして）
1. `npm run build` を実行し、`dist/` フォルダの中身一式をZIP圧縮する（`dist/index.html` がZIPのルート直下に来るようにする）。
2. itch.io のダッシュボードで新規プロジェクトを作成し、種別を「HTML」、埋め込み方式を「This file will be played in the browser」に設定してZIPをアップロードする。
3. ビューポートサイズは 420x900 程度を目安に設定する（レスポンシブ対応済みなので広めでも表示は崩れない）。
4. 価格設定（無料/投げ銭/有料）、公開範囲（Draft/Restricted/Public）は人間が判断して設定する。**この判断・実行はオーケストレーターの対象外。**

## 5. Print & Play（印刷して遊ぶ版）
- `docs/print-and-play.html` をブラウザで開き、印刷（Ctrl+P / Cmd+P）するとタイル16枚・4x4盤面・ルール要約を印刷できる。
- 実際の印刷所への入稿・発注は人間が行うこと（オーケストレーターは入稿データの下書き作成までを担当する）。
