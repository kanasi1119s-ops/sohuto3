# デバッグログ

3ラウンド制で実施。各ラウンドは Vitest によるユニットテスト全件実行と、Playwright（Chromium headless、
プロジェクトには追加せず一時スクリプトとして実行）による手動スモークテストを組み合わせて検証した。

## Round 1（観点: 機能検証）

| # | 問題 | 再現手順 | 重大度 | 対応 | 修正コミット | 再検証結果 |
|---|---|---|---|---|---|---|
| 1 | バックアップ書き出しがクリックしても発火しないことがある | `document.createElement('a')` で作った要素をDOMに追加せず `.click()` していたため、ブラウザによってはダウンロードが開始されない | 中 | `document.body.appendChild(a)` してからクリックし、直後に `remove()` する形に修正（`src/App.tsx`） | 本サイクルのfeatコミットに含めて修正 | Playwrightでダウンロードイベント発火を確認、成功 |

その他: `npm run typecheck` / `npm run test`（14件）/ `npm run build` はすべて成功。顧客追加→見積作成→
設定保存→バックアップ書き出し→PDF出力の主要フローを通しで確認し、上記1件以外の問題は検出されなかった。

## Round 2（観点: 異常系・境界値）

| # | 問題 | 再現手順 | 重大度 | 対応 | 修正コミット | 再検証結果 |
|---|---|---|---|---|---|---|
| 1 | 数量・単価に負の数を入力しても弾かれない | 見積編集画面で数量に `-2`、単価に `-500` を入力 | 低 | クラッシュはしないため今回は既知課題としてバックログに記載（README「既知の制約」に明記）。入力バリデーションの追加は次サイクル候補 | - | - |

検証した項目（問題なし）:
- 空の顧客名で「追加」→ 何も登録されない（プレースホルダー行のみ表示）
- 300文字超＋ `<script>` タグを含む顧客名 → Reactの標準エスケープによりテキストとして安全に表示され、
  スクリプトは実行されない（XSS確認）
- 品目0件のまま見積書を保存 → クラッシュせず保存できる
- ブラウザリロード（アプリ再起動相当）後もIndexedDBのデータが復元される
- バックアップ書き出し→読み込みの往復（Vitestユニットテストで検証、`src/lib/backup.test.ts`）

## Round 3（観点: クリーン環境・回帰・オフライン動作）

| # | 問題 | 再現手順 | 重大度 | 対応 | 修正コミット | 再検証結果 |
|---|---|---|---|---|---|---|
| - | 検出なし | - | - | - | - | - |

実施内容:
- リポジトリを別ディレクトリに `git clone`（今回のブランチ）し、README記載の手順どおりに
  `npm ci` → `npm run check` → `npm run build` を実行。すべて成功（クリーン環境での再現性を確認）。
- Playwrightで全リクエストをインターセプトし、`localhost` 以外へのリクエストが一切発生しないことを
  確認した上で、顧客登録→見積作成→保存の一連の操作が完了することを確認（「外部通信ゼロ」「オフライン動作」
  の主張を裏付け）。
- Round 1・2 で実施した操作を組み合わせて再度実行し、修正によるデグレードがないことを確認。
