# デバッグ・テストプレイログ（3ラウンド）

対象: コネクロス (ConneCross) v1.0
実施方法: ユニットテスト（vitest）、AI同士の自動対戦シミュレーション（`npm run simulate`）、ブラウザ実機での操作確認（Playwright + Chromium、スマホ幅390pxでスクリーンショット確認）

## Round 1（初回テスト）

### 実施内容
- ロジックユニットテスト13件（盤面生成、カード配布、隣接判定、連結グループ計算、終了条件、フォールバックルール）
- AI（greedy）同士のシミュレーション 2,000試合
- ブラウザでの手動プレイフロー確認（メニュー→対局→終局モーダル→ルール表示）

### 発見した問題

| # | 内容 | 重大度 |
|---|---|---|
| 1 | 盤面49マス（奇数）のため先手が後手より1手多く石を置ける構造になっており、シミュレーションで **先手55.4% / 後手41.7%** という無視できない勝率の偏りが発生 | 中（バランス上重大、クラッシュ等ではない） |

### 修正内容
- 盤面中央 (4,4) に、セットアップ時点でグレーの障害物を1個あらかじめ配置する仕様に変更（`applyCenterHandicap`, `src/game/engine.ts`）。実際に使えるマスを48（偶数）にし、先手・後手が必ず同じ24手ずつを行う構造にした。
- `docs/rules.md` のセットアップ手順・終了条件・プレイ例・バランス設計の節を修正内容に合わせて更新。
- ユニットテストのうち、中央マス (3,3)[0-indexed] を石の配置先に使っていた3件を、影響を受けない別マスに書き換え、期待値（空きマス数48等）を修正。

## Round 2（Round 1修正の確認＋再テスト）

### 実施内容
- Round 1で修正した箇所を含む、全13件のユニットテストを再実行
- AI（greedy）同士のシミュレーションを同条件で再実行（2,000試合）
- 追加検証: greedy AI vs random AI のシミュレーション（各1,000試合、先手・後手を入れ替えて2パターン）で「配置判断の実力が結果に反映されるか（支配戦略ではなく選択の質が勝敗を分けるか）」を検証

### 結果

| 項目 | 修正前 (Round1) | 修正後 (Round2) |
|---|---|---|
| 先手勝率 | 55.4% | 49.9% |
| 後手勝率 | 41.7% | 46.7% |
| 引き分け率 | 2.9% | 3.4% |
| 平均ターン数 | 49.0 | 48.0 |

先手/後手の勝率差が **13.7ポイント → 3.2ポイント** に縮小し、実用上問題ないレベルまでバランスが改善したことを確認。

greedy vs random では、先手・後手を入れ替えても一貫して **greedy側が約90%勝利**（91.5% / 89.4%）しており、カードの引き運だけでなく「どこに置くか」という配置判断の質が勝敗を大きく左右することを確認。これは「運と戦略の比率」の設計仮説（8節）を裏付ける結果。

### 発見した新規問題
- なし（Round 1の修正によって新たな不具合は確認されなかった）

## Round 3（回帰確認・最終判定）

### 実施内容
- 全13件のユニットテストを再度実行し、Round 1・2の修正がリグレッションを起こしていないことを確認
- `npm run build`（型チェック含む）でビルドが通ることを確認
- Playwright（Chromium、390×844のスマホ想定ビューポート）で以下を自動操作し、コンソールエラー・ページエラーが0件であることを確認
  - メニュー画面の表示とCPU対戦設定
  - 盤面中央マスが最初から障害物として表示されていること（Round1の修正が実際のUIに反映されているか）
  - カードをめくる → 合法マスがハイライトされる → クリックで配置 → CPUが自動で応手する、という一連のゲームプレイフロー
  - 盤面が埋まるまでの自動プレイでゲーム終了モーダルが表示され、最大連結・総石数・勝者が正しく表示されること
  - ルール説明モーダルの開閉

### 結果
- ユニットテスト: 13件全て成功
- ビルド: 成功（TypeScriptエラーなし）
- ブラウザ動作: コンソールエラー・ページエラー0件。中央マスの事前ブロック、カード配布、合法手ハイライト、CPU対戦、終局判定・結果表示、ルールモーダルの開閉すべて正常動作を確認
- 重大バグ（クラッシュ、進行不能、勝敗の誤判定、終わらないゲーム）: **0件**

### 最終判定
Round 1〜3を通じて重大バグはゼロ。バランス上の偏り（Round1で発見）はRound2で修正・検証済み。**Exit基準を満たしたと判断する。**

## 既知の軽微な課題（持ち越し）

- AIは現状「greedy（貪欲法）」1レベルのみ。難易度選択（弱め/強め）は次サイクル以降の拡張候補。
- オンライン対戦（別々の端末での対戦）はMVP対象外。現状はホットシート（同一画面での交代プレイ）のみ。
- シミュレーションは全てAI同士（greedy/random）によるものであり、**人間同士の実プレイによる「面白さ」の検証は未実施**。これは人間によるテストプレイが必要な項目として日次レポートに明記する。
