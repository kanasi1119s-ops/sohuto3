# デバッグ・テストプレイログ

QA/Playtesterフェーズとして計3ラウンドのデバッグ・自動シミュレーションを実施した。

## ラウンド1: 初回テスト → 致命的な必勝バグを発見

**実施内容**: ユニットテスト13件作成・全パス。その後 `npm run simulate` でAI同士(greedy vs greedy)を2000回対戦させたところ、**先手(A)が2000戦2000勝（100%）、しかも毎回まったく同じ11手で終了する**という明らかに異常な結果を検出した。

| 項目 | 内容 |
|---|---|
| 発見した問題 | ①フォージが「開いた三（両端が空きマスの3連結）」への対抗策を無効化する致命的な必勝パターン ②greedy AIが乱数を一切使わず完全に決定論的なため、2000通りの異なるシードを与えても実質1パターンしか生成されない |
| 重大度 | ①致命的（ゲームとして成立しない） ②重大（シミュレーションの統計的信頼性がない） |
| 再現手順 | 盤面をログ出力できる再生スクリプトで手順を再現。B(後手)が相手の開いた三の片端を単独の石でブロック→A(先手)がその石を**その場でフォージして取り消し**、空いた/もう一方の端に自分の石を置き、1手で4連結（オープンフォー）を作る→次の手で確定勝利、という手順が毎回再現された |
| 根本原因 | フォージの制限が「3連結以上のグループに属していないこと」だけで、置かれた直後の石でも即座にフォージ対象にできてしまい、「ブロック」という防御行為そのものを無力化できてしまう設計だった |

### 修正内容
1. **ルール変更**: フォージ対象になるための条件に「置かれてから2ターン以上経過していること（1ターンの猶予期間）」を追加。`docs/rules.md` / `src/game/rulesText.ts` を更新し、`GameState` に `placedOnTurn` を追加して経過ターン数を追跡するようエンジンを拡張（`src/game/engine.ts`）。
2. **AIの安全確認**: 「自分の手の直後に相手が即座に勝てないか」「相手がオープンフォー（阻止不可能な4連結）を作れないか」を1手先読みでチェックする `canWinImmediately` / `hasOpenFour` / `canForceWinNextMove` を実装し、AIが自殺手・相手への必勝形提供を避けるようにした。
3. **AIのタイブレーク**: greedy AIの評価が同点（上位2%以内）の場合はシード付き乱数でランダムに選ぶよう変更し、同一AI同士の対戦でも試行ごとに異なる展開になるようにした。

## ラウンド2: 修正確認 + 新規問題の検出

**実施内容**: 修正後、同じ再生手順で再テストしたところ、致命的な必勝パターンは解消（B(後手)のブロックが機能し、フォージも通常の駆け引きの範囲で使われるようになった）。

その後、`npm run simulate 1500 500` でAI同士を再度大量対戦させ、以下を確認した。

| 項目 | ラウンド1(修正前) | ラウンド2(修正後) |
|---|---|---|
| greedy vs greedy 先手勝率 | 100.0% | 51.0% |
| greedy vs greedy 平均手数 | 11.0手（常に固定） | 16.2手（12〜31手で変動） |

新たに、**MAX_TURNS定数の計算ミス**を発見した（重大度: 軽微）。random vs randomのシミュレーションで最長手数が56手を記録したが、定数上の理論上限は55手だった。原因は、開幕の「スワップ」アクション自体が配置を伴わない特殊な1手であることを上限計算に含め忘れていたため（正しくは 49配置+6フォージ+1スワップ=56手）。`MAX_TURNS` 定数・`docs/rules.md`・テストを修正した。

## ラウンド3: 再テスト（回帰確認）

**実施内容**: `npm run simulate 2000 1000` で計8000試合以上を実行し、ラウンド2の修正が安定していること、新たな回帰がないことを確認した。全試合でエラー・無限ループ（`applyAction`がエラーを返す、または `MAX_TURNS+10` を超えて終了しない）は0件。

### 最終シミュレーション結果（ラウンド3・n=1000〜2000）

| 対戦カード | 試行数 | 先手勝率 | 後手勝率 | 引分 | 平均手数 | 最長手数 |
|---|---|---|---|---|---|---|
| greedy vs greedy（パイルール有り） | 1000 | 51.8% | 48.2% | 0% | 16.3 | 31 |
| greedy vs greedy（パイルール無し・比較対照） | 1000 | 56.3% | 43.7% | 0% | 15.7 | 31 |
| random vs random（堅牢性チェック） | 2000 | 47.6% | 52.3% | 0% | 42.6 | **56**（理論上限と一致） |
| greedy(A) vs random(B) | 1000 | 100.0% | 0.0% | 0% | 11.1 | 23 |
| random(A) vs greedy(B) | 1000 | 0.0% | 100.0% | 0% | 11.7 | 24 |

**分析**:
- **先手/後手バランス**: パイルール有りだと51.8% / 48.2%とほぼ互角。パイルール無しだと56.3% / 43.7%まで先手有利に傾く。**パイルールが先手有利を約4.5ポイント緩和している**ことを定量的に確認できた（設計仮説どおり）。
- **終端性**: random vs randomの最長手数は理論上限のMAX_TURNS=56と完全に一致し、それを超える試合は1件もなかった。ゲームが必ず有限手数で終わるという設計上の保証がシミュレーションでも裏付けられた。
- **AIの強さのサニティチェック**: greedyはrandomに対して2000戦2000勝(100%)で、意図通り明確に強い。
- **支配戦略**: フォージ使用率はA平均1.15回・B平均1.36回（パイルール有り）で、両者とも限られたフォージ権を有効に使っており、「常に配置だけが最善」という支配戦略には陥っていない。

### 既知の制約・持ち越し課題
- greedy AIは1手先読みの安全確認のみで、2手以上先の詰み筋（本ラウンドで発見したものより複雑なパターン）を見逃す可能性が理論上残っている。プレイ体験上は大きな支配戦略は確認されていないが、今後さらに大量の対戦・多様な初手からの検証が望ましい。
- 「面白さ」そのものはAIシミュレーションでは判定できないため、**人間同士のテストプレイを公開前に必ず実施すること**を強く推奨する（日次レポート参照）。
